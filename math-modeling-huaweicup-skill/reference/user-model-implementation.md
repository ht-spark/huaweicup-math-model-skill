# 用户既定模型实现模式

当用户已经完成当前小问的模型设计，并要求依据其上传模型进行具体实现时使用本模式。目标是把用户模型忠实、可复核地映射为数据处理、算法、代码、结果和验证证据，而不是重新选模。

## 进入条件

满足以下任一条件即可进入：

- 用户明确说明“模型已经建立”“按我上传的模型实现”或同等意图；
- `upload_material/` 中存在与当前小问唯一对应的 `用户模型Qn.*`，且用户要求执行该小问。

多个文件共同描述同一模型时全部读取。文件与小问对应关系不唯一、版本互相冲突或关键页无法读取时，列出冲突并等待用户确认，不自行选择版本。

## 模型实现合同

编码前从用户材料中提取并在 `结果说明.md` 记录：

1. 当前小问的输入、输出和评价目标；
2. 变量、参数、索引集合、单位和取值范围；
3. 假设、目标函数、约束、方程、递推关系、初始/边界条件；
4. 数据字段与数学符号的对应关系；
5. 用户指定的算法、求解器、流程、超参数和终止条件；
6. 题目要求的结果文件、表格、图形和精度；
7. 明确缺失、相互矛盾或只能由实现者选择的内容。

将每一项标为：

- `specified`：用户模型已经明确，必须忠实实现；
- `implementation_choice`：数学结构不变，但代码层面必须选择；
- `blocking_ambiguity`：不同理解会改变模型或核心结论，必须由用户确认；
- `conflict`：与题目硬约束、数据事实或另一处用户定义冲突。

## 允许与禁止的动作

允许：

- 选择数值容差、数据结构、函数拆分、日志方式等不改变模型含义的工程细节；
- 为可复现性固定随机种子，增加断言、小算例、残差检查和敏感性分析；
- 提出替代模型或修正建议，但必须与实际实现分开陈述，未经批准不得采用；
- 用权威来源补充公开常数、标准定义或算法实现细节，但要登记来源和适用条件。

禁止：

- 把目标函数、约束、变量含义、关键参数或核心算法换成更熟悉的版本；
- 因结果不理想而静默调参、删异常样本、改评价指标或改变验证切分；
- 将检索到的论文模型冒充用户提供的模型；
- 对未给出的关键公式、边界条件或权重进行会改变结论的猜测。

阻断性问题出现时停止编码，并向用户给出：原文位置、两种可能解释、各自对实现或结果的影响，以及需要确认的最小问题。非阻断实现性选择可以采用常规、可逆方案，但必须进入人工审核包。

## 实现与验证

建立“模型—实现对照表”，至少包含：用户模型条目、源文件位置、代码文件/函数、数据字段、验证方法和状态。验证分成两层：

1. **实现忠实性**：公式、约束、索引、单位、边界和算法步骤是否与模型实现合同一致；用手算或小算例验证核心映射。
2. **模型适用性**：在题目数据上检查可行性、误差、稳健性、残差、基线比较或其他适用证据。适用性不足应缩小结论边界或提交用户决定，不自动换模。

人工审核包应特别列出所有 `implementation_choice`、忠实性验证结果、模型适用性风险，以及任何尚未采用的改进建议。

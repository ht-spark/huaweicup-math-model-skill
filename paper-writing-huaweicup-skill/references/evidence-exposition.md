# 证据化叙事与关键选择说明

本文件用于把已有建模过程写成可复核的论证，而不是软件操作记录。撰写完整报告、某小问的分析—建模—求解—结果，或审查图表是否真正参与论证时读取。这里只组织已有证据；不得补做实验、推测模型内部机制或生成建模产物中不存在的结论。

## 核心规范

论文不仅要给出答案，还要让评审能够判断关键选择为什么成立。对足以影响模型、结果或结论的选择，按以下链条组织：

```text
待判断的问题
→ 选择该处理或模型的题意、数据或机理依据
→ 能区分候选解释的证据
→ 从证据得到的判断
→ 该判断如何决定下一步
→ 尚未覆盖的范围
```

这里的“思考过程”是经过证据支持的决策逻辑，不是按时间顺序复述尝试、软件点击、调参经历或主观感受。常规且不影响结论的操作可以简述；关键选择不能只写“经过分析”“效果较好”或“因此采用”。

## 选择需要展开的决策点

优先说明会改变后续模型或结论的节点，例如：

- 数据清洗、尺度变换、样本划分或变量构造为何必要；
- 某项数据结构或机理特征为何支持当前模型；
- 候选模型、参数方案或优化策略为何取舍；
- 复杂模型是否学到与任务有关、且不依赖泄漏或偶然相关的结构；
- 结果是否满足约束、优于基线并在合理扰动下保持稳定。

不要求每一步都展开证明。若某项选择由题目直接规定、属于不影响结论的常规实现，或没有可用证据，则简洁说明其依据或记录证据缺口，不用装饰性图表制造“分析充分”的印象。

## 让证据与主张匹配

先写清要判断的主张，再选择能够回答它的证据；不得从已有图形反向拼凑故事。

| 待判断的主张 | 可采用的已有证据 | 不能单独推出的结论 |
| --- | --- | --- |
| 预处理确有必要且处理合理 | 处理前后的统计量、分布或信号对比，以及对模型结果的对照 | 图形看起来更整齐不等于性能或真实性提高 |
| 特征具有区分度或解释价值 | 与变量性质匹配的分布、相关结构、类内类间指标或受控对照 | 二维投影中分开不等于原空间中必然可分 |
| 候选模型更适合当前任务 | 同一数据划分、指标和约束下的基线或候选模型比较 | 单个分数不能说明机制正确或所有情景均占优 |
| 复杂模型利用了任务相关信息 | 消融、扰动、特征归因、中间响应或机理一致性证据 | 仅凭中间特征图的形状不能断言模型识别了某种机制 |
| 表示具有迁移、聚类或域对齐性质 | 定量距离/判别指标、目标任务性能和统一设置下的辅助可视化 | PCA、t-SNE 等降维图不能单独证明高维表示具有该性质 |
| 方案可靠或稳定 | 约束回代、误差、重复运行、灵敏度、情景或外部验证 | “趋势明显”“效果良好”等评价词不能替代检验结果 |

图、表、统计量和实验不是互相替代的固定套餐。根据主张选择最短、最有判别力的证据组合；相同信息不重复展示。若某个图只能帮助观察而不能完成验证，应明确称为“辅助观察”，并与相应定量证据分开陈述。

## 图表的论证职责

每张正文图表只设一个主要问题。采用前逐项判断：

1. 它具体回答哪个“为什么选择”或“结论是否成立”的问题？
2. 图表中的哪些差异、趋势、阈值或数量关系构成证据？
3. 该证据将支持哪项选择、结论或适用边界？
4. 删除它后是否会损失实质论证？如果不会，通常不纳入正文。

不得机械套用热力图、直方图、PCA、t-SNE、网络特征图等组合。只有建模产物已经提供、内容可读、解释可靠且与当前判断直接相关时才采用。需要新增诊断图、消融或对照实验时，将其写入 `待补充材料.md`，不能由写作技能代做或假定已经完成。

## 段落写法

关键选择可以压缩为下列结构，但不得把它当成固定句式：

> 为判断【当前决策问题】，依据【题意、数据或机理】比较/检验【对象】。【图、表、指标或实验】显示【可核实的关键差异】；这说明【证据直接支持的判断】，因此后续采用【处理、模型或方案】。该证据尚未覆盖【范围】，相应结论仅适用于【边界】。

正文应呈现判断所需的信息，而不是宣称作者“深入思考”“理解模型”或“具有数据体感”。读者是否相信这些品质，应由证据链自然体现。

## 审查清单

- 关键模型选择是否至少有题意、数据、机理或对照证据之一，而非只报方法名？
- 数据处理是否说明了必要性和影响，而非罗列操作？
- 图表是否回答明确问题，并在图后连接到选择或结论？
- 可视化证据是否被误写成证明，尤其是降维图和模型内部响应图？
- 不同模型或处理方案是否在统一数据、指标和约束下比较？
- 是否把个人感受、复杂度或“高级感”误当作方法优越性的证据？
- 每项解释是否没有超过建模产物能够支持的范围？

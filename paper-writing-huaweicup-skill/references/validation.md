# 小问检验与结论边界

## 职责

验证对应小问的结果是否可信，并界定结论可适用到什么范围。此文件应作为“模型求解与结果分析”的组成部分加载，不单独形成全文末尾的集中检验章。

## 写作顺序

1. 按模型类型选择适用检验：误差、约束满足、基线对比、残差、交叉或滚动验证、稳定性、灵敏度、情景或泛化检验。
2. 报告检验数据或情景、评价指标、结果和解释。
3. 说明检验支持或削弱了哪一项结论。
4. 对不适用或未完成的检验，说明原因和由此产生的结论边界。

## 边界

不以“模型可靠”“效果良好”替代指标；不在结果出来后无说明地更换验证集、指标、约束或比较对象。

## 落地示例

### 示例一：预测模型的独立验证

**适用场景**：分类、回归或时间序列预测。

> 为检验【预测结论】，按【时间顺序/主体分组/预先固定比例】划分训练集与验证集，避免同一对象或未来信息同时进入两侧。模型选择统一采用【指标一】和【指标二】：【指标一】衡量【含义】，【指标二】用于识别【指标一无法反映的问题】。在验证集上，候选模型 A、B、C 的【主指标】分别为【数值】，最终模型同时取得【次指标数值】。残差图显示【有证据的结构】，说明模型在【范围】内能够支持【具体结论】，但对【样本稀少区间或外推区域】仍缺少证据。

### 示例二：优化方案的约束与稳定性检验

**适用场景**：整数规划、启发式算法、选址、调度或多目标方案。

> 首先逐项回代最优解，确认【覆盖、容量、守恒或取值】约束的违反数为【数值】。随后保持数据和停止条件不变，用【不同随机种子/基线算法】重复求解【次数】，核心目标的【均值±标准差或区间】为【数值】。当关键参数 $\lambda$ 在【范围】内变化时，方案的【主要结构】保持不变，而【成本或性能】变化【幅度】。这些结果支持“方案在给定参数邻域内稳定”，但不能推出其在【未检验情景】下仍为全局最优。

**写法解析**：验证对象必须对应一项正文结论；先说明数据或扰动怎样设置，再给指标和结果，最后明确它支持到哪一步。优化模型还应先检查可行性，再谈性能。

**可复用结构**：待验证结论 → 验证设计 → 指标与结果 → 对结论的支持程度 → 未覆盖范围。

**使用边界**：二选一或组合使用，以实际执行的检验为准。没有独立验证、重复运行或灵敏度结果时，只能说明缺失及其影响，不能套用示例数值结构伪造检验。

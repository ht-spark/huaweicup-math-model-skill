# 总体思路与问题关系

## 职责

仅在多个小问共享数据、模型或存在前后依赖时，说明整体拆解逻辑和结果如何交接。

## 写作顺序

1. 指出各小问的输入、输出及依赖关系。
2. 说明共同的数据处理、指标体系、基础模型或结果传递。
3. 用流程图或简短文字呈现从题目输入到最终交付物的路径。

## 边界

简单且彼此独立的题目可以省略本节；不提前展开每个小问的公式、算法细节或结果。

## 落地示例

### 示例：说明多问之间的数据流和结果交接

**适用场景**：后续问题复用前问的清洗数据、参数估计、评价指标或候选方案。

> 全文以【共同数据】为基础形成三层任务链。问题一先完成【数据校核与规律识别】，输出【中间指标 $A$】和【参数集合 $\Theta$】；问题二将 $A$ 与 $\Theta$ 作为固定输入，在统一的【评价指标】下比较【候选模型】，得到【预测结果或评价结果 $B$】；问题三进一步把 $B$ 写入【优化目标或情景约束】，形成【最终方案 $C$】。因此，问题一决定基础口径，问题二提供决策依据，问题三完成题目要求的最终交付。若问题一的【关键假设】不成立，问题二和问题三中依赖 $A$ 的结论均需重新计算。

可将技术路线压缩为：

```text
题目与附件 → 数据校核 → 规律/参数 A → 模型比较与验证 → 结果 B → 约束优化/情景分析 → 方案 C
```

**写法解析**：不仅列出每问采用的方法，还明确前问“输出什么”以及后问“怎样使用”；最后指出误差或假设会沿哪条路径传播。

**可复用结构**：共同输入 → 各问处理 → 中间输出 → 下游用途 → 依赖风险。

**使用边界**：只有存在真实依赖时才写结果交接。若各问彼此独立，应分别写小问分析，不人为拼成流程。

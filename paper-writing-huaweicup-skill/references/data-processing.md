# 数据处理

## 职责

说明从原始数据到可用于模型的分析数据之间发生了什么，并保证处理规则可追溯。

## 写作顺序

1. 说明本节使用的数据文件、字段、样本范围和数据粒度。
2. 描述缺失、重复、异常、时间对齐、单位换算或数据拼接的处理规则。
3. 说明特征构造、指标体系、标准化或编码的原因及对模型的作用。
4. 报告处理后的数据规模或关键统计特征；必要时用图表支持。

## 边界

不得静默删除数据；若处理规则被多个小问共用，可前置集中写，否则放在对应小问内。

## 落地示例

### 示例：多表、重复记录和时间对齐

**适用场景**：附件由主体表、事件表和多时点观测表组成，同一对象可能有多条记录。

> 本问使用附件【A】中的【主体编号、静态字段】和附件【B】中的【检查时间、观测值】。首先以【唯一编号】连接两表，并检查一对多关系；对完全重复记录保留首条，对同一编号同一时刻但数值冲突的记录列入待核对清单，不直接平均。随后以【基准时刻】为零点，将各次观测换算为相对时间 $t$；仅保留题目规定的【时间窗口】内记录。对缺失的【字段】采用【已执行的方法】处理，其依据是【缺失比例、字段类型或时间连续性】；【关键结局字段】缺失的样本不参与对应模型训练，并单独报告数量。最后依据【公式或业务定义】构造【特征】，经处理得到【样本数】个对象、【记录数】条观测和【特征数】个候选变量，具体字段与处理前后数量见表【编号】。

**写法解析**：段落依次说明输入、连接键、异常处理、时间口径、缺失规则、特征构造和处理后规模；每一步都给出规则以及为什么这样处理。

**可复用结构**：数据来源与粒度 → 合并键 → 重复/冲突 → 时间与单位统一 → 缺失和异常 → 特征 → 处理后规模。

**使用边界**：只写代码或处理记录中真实执行的步骤。不得把“删除缺失值”“归一化”等笼统动作写入正文而不说明对象、阈值、方法和影响样本数。

*范文依据：归纳自 E23107030070、E23900310014 的多表关联和多时点数据处理，以及 F22105330345 的重复记录与网络数据构造方式。*

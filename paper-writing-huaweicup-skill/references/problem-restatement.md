# 问题重述

## 职责

将题目文本转换为后续建模可执行的任务定义，明确要解决什么，而不提前回答如何解决。

## 写作顺序

1. 说明现实背景、研究对象和任务范围。
2. 交代题目给出的数据、条件、时间或空间范围及关键约束。
3. 按题目原意逐项列出小问的目标、要求输出和相互依赖关系。

## 边界

可压缩题面中的背景叙述，但不得改变任务条件；不在本节介绍具体模型、算法或计算结论。

## 落地示例

### 示例：从现实背景收束到可执行任务

**适用场景**：题面背景较长，包含多类数据、资源限制和多个递进小问。

> 【现实系统】需要在【资源或时间限制】下完成【核心业务目标】。题目给出【数据文件及其主要字段】，覆盖【时间、区域或样本范围】，并规定【不能改变的业务约束】。现需完成以下任务：第一，刻画【对象】的【规律或现状】，输出【指标、判断或预测】；第二，在第一问结果基础上建立【评价或决策任务】，给出【排名、参数或方案】；第三，将前述结果用于【优化、情景分析或推广】，输出满足【关键约束】的【最终交付物】。

**写法解析**：背景只保留造成建模需求的矛盾；数据和硬约束单独交代；每个小问写成“动作 + 对象 + 输出”，并说明依赖关系，但不提前出现模型名称。

**可复用结构**：现实矛盾 → 已知数据与边界 → 分问任务 → 每问交付物与依赖。

**使用边界**：不得把作者补充搜集的数据写成题目给定数据，也不得将后续采用的算法写进问题重述。题面中的数量、时间和约束应逐项核对原文件。

*范文依据：归纳自 C23910020010 的“问题背景—问题提出”和 F22105330345 的分问重述方式；示例已压缩背景并去除原题事实。*

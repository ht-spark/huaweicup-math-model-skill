# 模型求解与结果分析

## 职责

展示模型如何被实现和求解、得到什么结果，以及结果对题目意味着什么。本节承载每个小问的主要证据闭环。

## 写作顺序

1. 说明求解方法、关键算法配置、随机种子、停止条件或计算环境。
2. 给出题目要求的核心结果，并引用对应表格、图片或结果文件。
3. 解释数值、趋势、排序、预测或最优方案的题意与实际含义。
4. 若有备选方案，按预先定义的指标比较并说明选择依据。
5. 交代本问向后续小问传递的结果及限制。

## 边界

不能只贴图表、代码或数值；所有结论应可回溯至 `modeling_output/` 中的产物。

## 图表写作硬性要求

每个采用的图或表都必须完成“正文导入 → 图题/表题 → 必要的图注/表注 → 正文解读”闭环，具体规范和示例见 `figures-tables-formulas.md`。

- 导入句说明为什么展示该图表以及它服务于哪个比较或判断。
- 图题置于图下居中、表题置于表上居中；标题只写编号和简洁内容说明，不添加小问归属、必要条件或结论性措辞。必要信息放入导入句或图注、表注。
- 图注、表注解释理解图表所必需的编码、样本、单位、统计口径、缩写或来源，不重复结论。
- 正文解读提炼决定结论的差异、趋势、转折、异常或数量关系，并解释其对本问的意义；不能只写“见图”“如表所示”，也不逐项朗读全部数值。

当图和表表达同一结果时，说明二者各自承担的证据角色；若完全重复，只保留更适合支持结论的一种。

## 落地示例

### 示例：报告配置、比较结果和实际含义

**适用场景**：同一任务比较多个候选模型或方案，并需要选择一个结果传给后续小问。

> 在相同的训练集、测试集和【评价指标】下，分别求解方案 A、B 与 C。计算采用【软件/求解器】，随机种子设为【数值】，终止条件为【迭代次数、容差或时间】，其余关键配置见表【编号】。表【编号】显示，方案 C 的【主指标】为【数值】，相较方案 A 和 B 分别【提高/降低】【有证据的幅度】；同时其【次要指标】未超过题目给定的【阈值】。因此，C 的优势并非只来自某一项局部指标，而是在满足【硬约束】的前提下取得更好的【目标表现】。从题意看，这意味着【把数值翻译成服务能力、风险、精度或成本等实际含义】。后续问题使用方案 C 输出的【参数/排序/预测序列】，适用范围限定为【样本或情景范围】。

若结果由图支持，可继续写：“图【编号】表明，改进主要发生在【区间或对象】，而【另一范围】差异较小；因此不能将总体平均改善解释为所有样本均等改善。”

**写法解析**：先固定可复核的求解条件，再报告同口径比较；选择结论同时检查主指标和硬约束；最后解释数值的题意以及向后续问题传递什么。

**可复用结构**：求解条件 → 核心结果 → 同口径比较 → 约束核对 → 题意解释 → 下游用途和边界。

**使用边界**：不得根据图片目测补造数值，也不能只因某一指标最好就宣称方案整体最优。比较对象、数据划分和指标必须保持一致。

*范文依据：归纳自 C23910020010 的多方案指标比较、E23900310014 的模型筛选和 F22105330345 的选址结果解释。*

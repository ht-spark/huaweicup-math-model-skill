# 华为杯研赛 · 建模与求解（题目驱动流程）

面向中国研究生数学建模竞赛（华为杯）的**建模与求解**环节。流程：读题 → 数据画像 → 逐题思考建模 → 编码求解产出 → 生成说明。不覆盖论文写作与排版。

## 何时使用

- 用户明确提到华为杯、中国研究生数学建模竞赛或研赛，并需要建模、求解或结果验证
- 拿到赛题与数据，需要思考模型并产出图片和题目要求的结果
- 对已有模型做检验、灵敏度分析、备选方案对比
- 典型关键词：华为杯、中国研究生数学建模竞赛、研赛。

不用于：其他数学建模竞赛的通用请求、论文写作与排版，或未关联华为杯赛题的数据分析任务。

## 核心原则（最高优先级）

**1.具体问题具体分析：模型必须从题目本身的背景、机理和数据特点推导出来。严禁先划分题目类别再套方法-—不得把"识别题型 → 查表选算法"作为建模路径。**

**2. 代码实现、数值求解与可视化默认使用 Python；只有用户明确指定其他语言或工具时才调整。**

**3. 模型选择以题目机理、数据结构、样本规模和验证条件为依据。优先采用可解释、能由题目事实支持的数学模型；仅在数据和任务条件支持时使用机器学习或深度学习。**

**4. 虚拟环境、代码和生成产物均放在当前项目文件夹中；不修改用户提供的赛题和原始数据。**

## 工作流

### Step 1 读题

通读赛题全文，逐字理解背景，输出三样东西：

- **题目背景**：这道题在解决什么现实问题，整体的背景是什么，比如是某个经济学背景下的问题还是某个工程难题等
- **问题分解**：每个小问的要求是什么，要解决的问题是什么，小问之间的依赖关系
- **关键词划线**：题目中的约束条件、定量要求、必须给出的输出物清单、依赖的附件数据等

### Step 2 数据画像

逐文件检查数据，输出画像报告：

- 规模与结构：行列数、字段含义、主键、时间粒度或空间粒度
- 质量：缺失值比例与分布、异常值（3σ / 箱线图）、重复记录
- 统计特征：各字段分布、量纲差异、相关性、时序性 / 空间性 / 网络性
- 与问题的关联：哪些字段直接对应题目要求的量，哪些字段缺失需要推导

数据画像结论直接约束下一步的建模选择（样本量、噪声、结构决定模型）。

### Step 3 逐题思考建模

对每个小问，**从问题机理出发**独立思考，输出建模论证：

1. 这个小问的本质是什么量、受什么机制支配？
2. 从机理和数据特点出发，候选模型有哪些？各自的假设与本题事实是否吻合？
3. 结合数据画像的结论筛选：数据是否支撑该模型假设？假设不满足时如何调整？
4. 明确写出：符号表（符号、含义、单位）、数学表达（目标函数 / 约束 / 方程 / 递推）、**为什么这个模型适配本题**的具体论证

### Step 3A 建模验证（编码前）

为每个小问制定与模型类型相匹配的验证计划，并记录证据与结论；不适用的项目应说明原因。

1. **题意与量纲核对**：逐项映射模型输入、决策变量、输出和题目要求；检查单位、数量级、边界与约束是否一致。无法由原始数据直接观测的量，说明推导来源和误差风险。
2. **假设可辩护性**：把每项关键假设与题干事实或数据画像逐条对应。对独立性、线性、平稳性、同分布、完全信息等强假设，给出诊断方式或明确其适用边界。
3. **最小基线与反例**：设计一个简单、可解释的基线（如历史均值、规则策略、线性模型、贪心解或等权评价），说明主模型应在哪些指标上优于它；同时列出会使模型失效的极端或反例场景。
4. **可行性与可识别性检查**：确认参数可由现有数据估计、约束存在可行解、目标与约束没有冲突。优化模型先检查变量边界和可行域；预测模型先划分不泄漏的训练、验证和测试时段或样本。
5. **预先定义验证口径**：在编码前确定对照对象、评价指标、验证切分或模拟方案，以及何种结果会降低对结论的信心。预测可用滚动验证；优化可用已知小算例、下界或可行基线；评价可用换权重/换方法后的排序稳定性；机理模型可用历史或实测数据拟合与残差诊断。

### Step 4 编码求解与验证

1. 基于 Step 3 的模型生成对应的 Python 求解代码，确保实现、符号定义与数学表达一致。
2. 运行代码并做与风险相称的验证：至少检查数据读入、单位与约束；启发式算法或复杂模型应增加小算例、基线或交叉验证。
3. 将运行产物与题目要求逐项核对；清楚标出未满足的前提、无法验证的结论或仍需用户确认的数据含义。
4. 代码中的绘图环节直接使用本 Skill 已内嵌的完整 `nature-figure/` 组件：先读取 `nature-figure/SKILL.md`，再按其中路由读取所需资源和执行本地脚本。当前 Skill 固定选择 Python；该组件已随本 Skill 提供，不检查外部安装状态，也不使用外部路径或替代路线。竞赛适配规则见 `reference/figure-integration.md`。
5. 按 Step 3A 的预设口径执行验证，并将每项验证的输入、方法、指标、结果和结论写入说明文档。不要因结果不理想而在未说明的情况下更换验证集、指标或约束。

### Step 4A 代码与运行产物验证

根据模型类型选择适用检查，至少覆盖“实现正确性、解或预测的可信度、结论稳健性”三类证据。

1. **实现正确性**：检查字段映射、缺失值处理、单位换算、索引对齐和训练/测试边界；用手算或可独立求解的小算例验证核心公式。对优化与仿真，逐项检查约束、守恒关系、非负性、概率和等不变量。
2. **数值与求解可靠性**：记录求解器状态、收敛条件、运行时间和随机种子。启发式算法以多次独立运行比较目标值与波动，并和小规模精确解、松弛界或可行基线对照；数值迭代或仿真检查容差、步长或样本量变化后结论是否稳定。
3. **任务效果验证**：预测与分类在严格隔离的测试集上报告适用指标并检查残差或错误样本；时序任务采用滚动或前向验证。评价模型比较不同合理定权/标准化方案下的排序相关性。机理模型报告拟合误差并对照观测趋势或已知规律。优化模型报告可行性、目标值、基线改进和必要时的最优性界。
4. **稳健性与边界检查**：对关键参数、数据扰动或情景做敏感性分析；优先使用题意相关的情景，必要时补充 ±5% / ±10% 单因素扰动。报告结论是否翻转；若翻转，缩小结论的适用范围或回到 Step 3 重新建模。
5. **产物可复核性**：重跑代码确认结果可复现，核对输出文件名、字段、单位、精度与题目要求；抽查图表、表格和说明中的数字能追溯到运行产物。

### Step 5 产出

代码运行应产出题目要求的结果文件；当图表能说明关键结论或题目明确要求时，同时产出图片。

- **图片（适用时）**：每张图传达一个明确结论。使用内嵌 `nature-figure/` 的 Python 路线，并按 `reference/figure-integration.md` 覆盖为竞赛输出：中文字体 10–12pt，PNG 300 dpi，重点图额外导出可编辑的 PDF 或 SVG；运行其本地预检和渲染后质量检查
- **题目要求的输出结果**：严格按题目规定的格式（文件名、字段、单位、精度）生成结果文件；题目没规定格式的，用 CSV + 表头说明

### Step 6 结果说明

生成一份说明文档（Markdown），必须包含：

- **产物清单**：每个输出文件 / 每张图是什么、路径在哪
- **产物含义**：数值结果的具体解释（最优解是什么、预测值代表什么、排序意味着什么）
- **模型说明**：建立的模型完整表述（假设、符号、数学结构、求解方法与配置）
- **建模思路**：为什么这样建模——从题目机理和数据特点到模型选择的推理链条
- **检验结论**：误差指标、灵敏度分析（关键参数 ±5% / ±10% 扰动，结论是否翻转）
- **验证证据链**：对每项已执行验证写明验证目的、方法、数据或情景、指标、结果与结论；未执行或不适用的验证应说明理由。

## 规则

1. 用户提供的赛题与数据文件只读，不修改
2. 所有随机算法固定 `SEED = 42`，并在结果说明中记录随机性、超参数和求解器配置
3. **禁止以"题型 → 算法表"的路径选择模型**；每个模型选择必须写出来自本题的论证
4. 结果文件和 Step 6 的说明文档缺一不可；图表按题目要求或其对结论的支撑价值决定是否生成
5. 图表统一使用本 Skill 内嵌 `nature-figure/` 的 Python 路线，并遵循 `reference/figure-integration.md` 的竞赛覆盖规则；图表应中文正常显示、坐标轴带单位，并以 PNG 300 dpi 导出，重点图额外导出 PDF 或 SVG 矢量版
6. 数值结论必须附适用的误差、可行性或稳健性检验指标；若该类指标不适用，应说明原因并给出替代验证
7. 验证方案应在结果出来前确定；如因数据限制调整验证口径，必须记录调整原因和对结论的影响
8. 输出的结果说明文档一定要信息，保留所有细节，模型说明、建模思路、检验结论特别需要写详细，这份结果说明要满足写一篇优秀的数模报告的信息要求

## Do's and Don'ts

**Do**

- 先读题、再看数据、后想模型，顺序不可颠倒
- 启发式算法先用小算例验证；报告超参数与求解器配置

**Don't**

- **不读题不画像，先给题目贴类别标签再查表选方法**
- 模型假设与数据事实明显冲突仍继续硬套
- 只给数值结果，不提供结果文件和说明文档；在图表应支撑结论或题目要求时遗漏图表
- 用未来数据或泄漏特征做预测验证
